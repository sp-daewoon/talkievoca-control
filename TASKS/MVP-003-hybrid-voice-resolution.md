# MVP-003: Hybrid Voice Resolution

Status: In Progress
Owner repositories: `talkievoca-backend`, `talkievoca-apple`

## Outcome

A Watch user can use fast native dictation or record a short utterance for Qwen3-ASR, then hear the resolved word pronunciation and English example. Missing curated words can be generated by a local SLM with provenance-preserving cache storage.

## Backend scope

- Add `POST /v1/assistant/audio` with bounded audio validation and typed errors.
- Connect to Qwen3-ASR's OpenAI-compatible transcription endpoint.
- Route text and transcripts through the same DB, RAG-context, and SLM fallback pipeline.
- Persist SLM results as pending and keep them out of the trusted vocabulary index.
- Expose provider readiness in health diagnostics without leaking credentials.

## Apple scope

- Add a short foreground audio recorder for the Qwen path.
- Retain native dictation as the fast and always-available path.
- Play stored pronunciation audio and speak the English example on-device.
- Clearly report ASR/provider failures and allow immediate native-dictation fallback.

## Non-goals

- Pronunciation scoring, continuous background listening, or automatic recording on wrist raise.
- Storing user recordings.
- Supporting provider features unrelated to short one-word transcription, including diarization, timestamps, and realtime Chinese ASR.
- Automatically trusting SLM or ASR output.

- [x] Unknown Korean input resolves through local Ollama and is cached as pending.
- [x] Pending vocabulary is served from PostgreSQL but not indexed as trusted RAG vocabulary.
- [x] Qwen disabled/unavailable returns a standard 503 while text lookup remains healthy.
- [x] The watchOS simulator SDK build succeeds with App Intents metadata.
- [x] Local Qwen3-ASR transcribes both English `apple` and Korean `사과` audio through the real Kotlin endpoint and resolves both to trusted `apple` data.
- [ ] A physical Watch records a short utterance, receives feedback, and plays pronunciation plus example audio.

## Verified implementation

- Backend tests exercise the Qwen multipart client, audio controller, shared resolver, disabled-ASR error, and pending-cache persistence.
- Docker port 8080 resolved `강아지` through host Ollama, then served the cached result in 0.02 seconds.
- PostgreSQL stored the generated row as `slm/pending`; OpenSearch returned zero trusted vocabulary documents for it.
- The Watch app builds against the watchOS simulator SDK with App Intents metadata, short M4A capture, upload, stored-audio playback, and on-device English example speech.
- The pinned ARM64 Qwen3-ASR CPU service is running locally. `apple.m4a` completed Qwen → shared resolver in 3.6 seconds after startup; synthesized Korean `사과` completed in 1.7 seconds.
- The Java client is fixed to HTTP/1.1 because Java 21's h2c upgrade was incompatible with the provider nginx and caused multipart fields to be ignored.
- A narrow local adapter loads only the Qwen Rust model and reduced measured ASR memory from about 6.2 GiB to 2.1 GiB after settling while retaining English and Korean results.
- The updated app is installed on the paired Watch; one physical recording/playback run remains the final hardware acceptance.
