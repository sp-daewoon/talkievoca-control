단어 해석 파이프라인

모델을 먼저 호출하지 않는다. 확정 데이터가 가장 빠르고 신뢰할 수 있으며, RAG와 SLM은 저장 데이터에 없는 경우에만 뒤에서 보강한다.

Ordered resolver앞 단계가 성공하면 뒤 단계는 호출하지 않음
1. Normalize공백, 대소문자, 허용 문자와 최대 길이를 정리한다.
2. PostgreSQL정확한 단어와 curated alias를 조회한다.
3. OpenSearch뜻·예문·질문과 PDF의 의미 후보 최대 3개 + PDF 키워드 검색.
4. Ollama SLM문맥을 참고해 구조화된 단어 카드를 생성한다.
5. Cache & Returnpending으로 저장하고 같은 API 응답 계약으로 반환한다.
매칭 결과는 `exact`, `alias`, `cache`, `slm`으로 구분하며 Qwen 경로에는 `qwen_` 접두사가 붙는다.

RAG 데이터와 신뢰 경계

RAG에 많이 쌓이는 것보다 무엇이 사실인지 구분되는 것이 먼저다. 사용 횟수나 AI 생성만으로 trusted 상태가 되지 않는다.

  • 검수된 뜻과 예문·별칭

  • PostgreSQL: 원본·질문·출처 연결
  • OpenSearch: bge-m3 벡터 + 키워드
  • media_data: PDF·MP3 원본
←

Pending input

  • SLM 생성 단어 카드
  • ASR transcript 기반 질의
  • 재사용 가능, 자동 신뢰 금지
불변 규칙: `slm/pending` 데이터는 개인 캐시로 응답할 수 있지만, `/admin/`에서 뜻·예문·별칭을 수정 승인해 `manual/trusted`가 되기 전에는 trusted vocabulary index에 들어가지 않는다.

같은 OpenAI-compatible endpoint로 CUDA/vLLM Qwen3-ASR을 연결할 수 있다. API key는 backend 환경 변수에만 둔다.

현재 Compose는 Apple Silicon에서 Qwen3-ASR-0.6B Rust CPU 모델 하나만 적재하는 소형 API adapter를 제공한다. 제품 합격의 마지막 기준은 실물 Watch 녹음과 재생이다.

핵심 설계 원칙

API-firstApple과 Backend는 versioned HTTP 계약으로만 결합한다.
Fast path first이미 인식된 text에는 ASR을 다시 호출하지 않는다.
One resolverSiri, 앱, Qwen transcript는 같은 단어 해석 순서를 탄다.
Provenance before reuse생성 데이터를 캐시해도 trusted와 섞지 않는다.
Human promotionAI 생성 단어는 운영자 수정 승인 후에만 trusted가 된다.
Media is media발음 음원은 vector 문서가 아니라 재생 자산으로 관리한다.
Physical Watch is acceptance음성 UX 완료 여부는 simulator가 아니라 실물에서 판정한다.
